# Twitter Better List

X（旧 Twitter）の「リストから追加/削除」画面を使いやすくする Chrome 拡張機能です。
X の有料 API は使わず、Web クライアント自身が行っている GraphQL 通信と画面の DOM を利用します。

## 機能

### リスト追加/削除画面

- **名前順 / 新しい順 / 古い順** の並び替え
- **☆ お気に入り** でお気に入りだけを表示
- **お気に入り（★）** を最上部に固定
- リストごとに **#タグ** を追加し、タグ行のチップで絞り込み
  - 複数のタグを ON にした場合は OR 条件
  - すべて OFF のときは全リストを表示（初期状態）
  - **✎ タグ名変更** で、同じタグを全リストまとめてリネーム／削除
- **☆ お気に入り** フィルター中は、お気に入り内の登録順が優先されるため、並び順ボタンをグレーダウンして無効表示
- 初回のみ、スクロール末尾までの自動読み込み
  - 「さらに表示」がある画面では自動クリック
  - 仮想スクロール画面では末尾までスクロールして追加読み込み
  - 読み込み中は行を隠し、全件そろってから表示するため、件数や並びが途中で揺れません
- 2 回目以降はキャッシュだけを使ってすぐに表示（自動の再取得はしない）
  - 全件キャッシュがあるときは、拡張機能から追加ページの取得を要求しません
  - 同じ相手を開き直した場合は、X がメモリに持つ行を復元するだけなので数回のフレームで表示されます
  - 相手が変わった場合も、X 本体の「その人を追加済みか」の取得だけを 100 件単位で行います
  - 表示件数はキャッシュ済みの全件数を先に確定表示し、ネイティブ行が揃うまで行を隠すため、20 → 40 → 60 のような途中表示は出ません
- 右上の **↻** を押したときだけ、リスト一覧を手動で再取得
- 表示中のリスト件数とお気に入り件数を表示

ネイティブのチェックボックスと「保存」ボタンはそのまま残しています。
追加・削除の保存処理は X 本体が行うため、拡張機能側で独自のメンバー変更 API は呼びません。

### 自分のリスト一覧 (`/<ユーザー名>/lists`)

- 追加/削除画面と同じ **名前順 / 新しい順 / 古い順** を適用
- **☆ お気に入り** の絞り込みと先頭固定
- **#タグ** の絞り込み（OR 条件、初期状態はすべて OFF）
- 各リストの固定ボタンの左に **#** と **☆** を常時表示。その場でタグ編集・お気に入り登録が可能
- **✎ タグ名変更** でタグを一括リネーム
- 自分のリストページに、他ユーザーが作成したリスト（フォロー中のリストなど）が含まれる場合、
  **他人が作ったリスト** というタグを初回だけ自動で追加（あとから自由に編集・削除できます）
  - 以前のバージョンが自動追加したタグは書き換えません。過去のタグを勝手に消して、あとから同じ名前で作り直したタグまで失うのを避けるためです
- お気に入りを先頭固定しているときは、並び順ボタンをグレーダウン
- `/<ユーザー名>/lists` 形式の公開リストページにも適用
- リスト ID と全件数は、拡張機能のキャッシュ、X の画面が持つリスト情報、
  `ListsManagementPageTimeline` / `ListOwnerships` 応答から補完
  - キャッシュがまだ無い初回でも、行は「読み込み中」のまま止まらず、名前順で表示
  - ID が補完されると、お気に入り・タグ・新しい順/古い順が有効になる
  - X の仮想スクロールで画面に載っている行だけを数えず、取得済みの全リスト数を表示
  - 「自分のリスト」より上に出る「新しいリストを見つける」は並び替え・フィルターの対象外
  - 「新しいリストを見つける」は既定で折り畳んで表示。設定で完全に非表示にできる
  - スクロール中は X の仮想スクロールを邪魔せず、停止後に並びを整えるため、行の重なりや一瞬の欠落が起きにくい

### 左サイドバー

- 最下部の「More / その他のメニュー項目」に入っている項目を、**ポストボタンの上に展開**
- 元の「More」ボタンは非表示
- 行は X の標準ナビゲーションボタンを複製して作るため、幅・高さ・アイコン位置・ホバーが標準項目と揃う
- クリック時は X のネイティブメニュー項目をクリックするため、X 側の画面遷移・モーダル・外部リンクの挙動をそのまま利用
- サイドバーが折りたたまれている場合はアイコンのみ、広い画面ではラベル付きで表示
  - 展開時の文字サイズ・太さ・行間・余白は、X の通常のサイドバー行から実測して合わせます
  - 文字サイズは X の通常範囲（12〜20px）にクランプし、CPT の「ナビゲーションバーで通常の文字スタイルを使う」で 15px などに縮小された場合も同じサイズに追従します
  - CPT などがネイティブ側を 20px より大きくしても MORE だけ巨大化しません
- 折りたたみ時は X の nav の内容幅にセクション幅を同期し、標準項目と同じ位置にアイコンを中央揃え
- 展開項目は独自のスクロール領域を持たず、X のサイドバー全体と一緒に 1 本のスクロールバーで移動
- **Control Panel for Twitter (CPT)** が非表示にしている項目は、計算済みスタイルを確認して一覧から除外
- CPT の設定変更時は自動で読み直し、可能な限り競合しません

### 設定ポップアップ

ツールバーの拡張機能アイコンから以下を変更できます。

- 既定の並び順
- お気に入りを先頭に固定するか
- 未取得リストの自動読み込み ON/OFF
- サイドバー展開の ON/OFF（オフなら標準の「More」メニューのまま）
- リスト一覧ページの「新しいリストを見つける」を完全に隠す ON/OFF
- リストキャッシュの削除
- お気に入り・タグ・設定のエクスポート / インポート（JSON をクリップボードで移動）

## インストール

1. リポジトリの **Code** → **Download ZIP** をクリック
2. ZIP を展開する
3. Chrome で `chrome://extensions` を開く
4. 右上の「デベロッパー モード」を ON
5. 「パッケージ化されていない拡張機能を読み込む」をクリック
6. このフォルダ（`manifest.json` があるフォルダ）を選択
7. X を再読み込み

Chrome 111 以降が必要です（MAIN world の content script を利用するため）。

## 使い方

1. X で対象アカウントのプロフィールを開く
2. 「⋯」→「リストから追加/削除」を開く
3. 上部のツールバーで並び順を変更
4. 行右端の **#** でリストにタグを追加（スペース・カンマ区切り）
5. タグ行のチップを ON にして絞り込み、**クリア** で解除
6. **☆ お気に入り** でお気に入りだけを表示
7. 行右端の **☆** でお気に入りに追加
8. チェックを入れて「保存」すると、X の通常処理で追加・削除される

別のブラウザへ移動するときは、設定ポップアップの **バックアップ / 移動** で
エクスポートした JSON をコピーし、移動先で貼り付けてインポートします。
お気に入り・タグ・設定だけを移動し、リストキャッシュは含みません。

サイドバーの展開項目は、X の「More」メニューに表示される項目を読み取って生成します。
CPT の設定変更は自動で反映されます。X 側でメニュー項目そのものが大きく変わった場合は、
ページを再読み込みすると再取得されます。

追加/削除画面の初回表示では、全件を取得してから一覧を表示するため数秒かかることがあります。
2 回目以降はキャッシュだけを使い、自動では再取得しません。X 側でリストを追加・改名・削除した場合は、右上の **↻** を押して手動で更新してください。
リストキャッシュはログイン中の閲覧者ごとに共有され、追加対象のユーザーごとには分かれません。
全件取得は追加対象ではなく閲覧者自身を対象に行うため、別の相手を開いても同じキャッシュを再利用します。
キャッシュは `chrome.storage.local` に保存されるため、ブラウザを終了して起動し直しても残ります。

キャッシュの「全件取得済み」は、次のいずれかを満たしたときだけ設定します。

- `ListOwnerships` のページ送りが Bottom cursor まで完了し、途中で打ち切られていない
- `ListsManagementPageTimeline` の一覧応答で置き換えた
- X のタイムライン終端（`TimelineTerminateTimeline`）または cursor なしを検出した

先頭ページの件数が要求件数より少ないだけでは「全件」と判断しません。
全件済みになった後は、ダイアログを開くたびの再確認や自動の全件取得は行いません。
未完了のキャッシュは、自動読み込み ON のときだけ最大 6 時間に 1 回補完し、
失敗・途中終了が続いてもダイアログを開くたびには再試行しません。OFF のときは自動取得を行いません。
手動の **↻** はこの制限の対象外です。
自分のリストページ由来の「他ユーザーが作成したリスト」の情報は、追加/削除画面用の全件取得で
上書き・削除されないように保持します。

## データとプライバシー

- 設定・お気に入り・タグ・リストキャッシュは `chrome.storage.local` にのみ保存
- エクスポート JSON にリストキャッシュは含めない（お気に入り・タグ・設定のみ）
- 外部サーバーへの送信は行わない
- 認証トークンを独自に外部送信しない
- リスト取得は、X のページ内で使われている GraphQL リクエストの仕組みを利用
- 追加・削除はネイティブの「保存」に任せる


### 既知の制限

- X の画面構造や GraphQL のクエリ ID が変更されると動作しなくなる可能性があります
- リストの追加・削除は 1 件ずつのネイティブ操作のみ（一括変更は行いません）
- お気に入りとタグはログイン中のアカウント単位で保存されます
- 初回のみ全件取得のため数秒待つことがあります。2 回目以降に最新のリスト構成が必要なときは **↻** を押してください。完全なキャッシュは自動では再確認しません
- 自分のリスト一覧では `ListsManagementPageTimeline` の応答から ID と全件数を補完します。ほかのユーザーの公開リストページでは画面データが揃うまで一部の行に ID が付かず、お気に入り・タグ・新旧順が一時的に使えないことがあります。反映されない場合は **↻** で再スキャンしてください
- サイドバーの展開項目は、表示中の画面の「More」メニュー内容を基準にします。X 側の仕様変更でメニューが開けなくなった場合は、ページを再読み込みしてください
